# SP/1 — JSI Signaling Protocol (Worker HTTP API)

Version: SP/1 · Status: normative for M1–M3 · Governing decisions: PLAN.md §3 (D2–D8, D13)

The signaling worker brokers exactly one SDP exchange per session, then forgets.
It is stateless between requests; all state lives in one KV namespace (`SESSIONS`)
with a 90 s TTL. **There is no DELETE endpoint — TTL is the forget mechanism (D5).**

Base URL: default hosted instance set at M1.8 (e.g. `https://jsi-signal.<acct>.workers.dev`);
all clients MUST allow overriding (`--server`).

## Token

- 6 characters from Crockford Base32: `0123456789ABCDEFGHJKMNPQRSTVWXYZ` (no I, L, O, U).
- Generated by the **worker** using `crypto.getRandomValues` (D3); on KV collision,
  regenerate (max 3 attempts, then `500`).
- Input handling: uppercase, trim, validate against `^[0-9A-HJKMNP-TV-Z]{6}$` before lookup.

## Endpoints

### `GET /v1/ice`
Returns ICE server configuration. Called by **both** sides *before* creating an
offer/answer (non-trickle embeds candidates in SDP — creds must exist first, D6).

Response `200`:
```json
{
  "iceServers": [
    {"urls": ["stun:stun.cloudflare.com:3478"]},
    {"urls": ["stun:stun.l.google.com:19302"]},
    {"urls": ["turn:turn.cloudflare.com:3478?transport=udp", "turns:turn.cloudflare.com:5349?transport=tcp", "..."],
     "username": "<128-hex>", "credential": "<128-hex>"}
  ],
  "ttl": 3600
}
```
Worker mints TURN credentials per request:
`POST https://rtc.live.cloudflare.com/v1/turn/keys/{TURN_KEY_ID}/credentials/generate-ice-servers`,
header `Authorization: Bearer {TURN_API_TOKEN}`, body `{"ttl": 3600}` (D7).
Worker returns the full URL list; **clients filter `:53` entries if their platform
blocks them (browsers do, D8)**. `ttl` is advisory — CF's response does not echo it.

### `POST /v1/sessions`
Sender publishes its offer.
```json
// request
{"offer": {"type": "offer", "sdp": "v=0\r\no=- …"}}
// 201 response
{"token": "7KQX2A", "expiresAt": "2026-07-18T12:01:30Z"}
```
Validation: `offer.type == "offer"`, `sdp` is a string ≤ 32 KiB.
KV write: key `s:{TOKEN}`, value `{"offer":{…}}`, `expirationTtl: 90`.

### `GET /v1/sessions/{token}/offer`
Receiver fetches the offer. → `200 {"offer": {…}}` · `404 session_not_found`.

### `POST /v1/sessions/{token}/answer`
Receiver publishes its answer. Body: `{"answer": {"type": "answer", "sdp": "…"}}`.
→ `201 {}` · `404 session_not_found` (unknown/expired token) · `409 answer_exists`.
KV write: key `a:{TOKEN}`, value `{"answer":{…}}`, `expirationTtl: 90`.
(Separate key from the offer — avoids KV's 1 write/s/key limit on fast exchanges.)

### `GET /v1/sessions/{token}/answer`
Sender polls. → `200 {"answer": {…}}` · `404 answer_not_ready` (session exists, no
answer yet) · `404 session_not_found`.

## Client behavior (normative)

- Sender polls the answer every **1.0 s** until `expiresAt`, then fails with
  "signaling timeout" (CLI exit 2). No retry storms: max 1 in-flight poll.
- Both sides SHOULD filter `:53` ICE URLs when running in a browser.
- Future optimization (NOT in v1): `GET …/answer?wait=25` long-poll held open
  server-side to cut request volume. Reserved; clients must not send it yet.

## Errors

All errors: `{"error": {"code": "<code>", "message": "<human readable>"}}`.

| HTTP | code | Meaning |
|---|---|---|
| 400 | `invalid_body` | malformed JSON / schema violation |
| 400 | `invalid_token` | token fails alphabet/length check |
| 404 | `session_not_found` | unknown or expired token |
| 404 | `answer_not_ready` | session exists, answer not posted yet |
| 409 | `answer_exists` | answer already posted for this session |
| 429 | `rate_limited` | rate-limit binding tripped |
| 500 | `internal` | unexpected (incl. token collision exhaustion) |

## Cross-cutting

- **Rate limiting**: Workers `ratelimits` binding on `POST /v1/sessions`,
  `POST …/answer`, and `GET /v1/ice`; limit 60 req / 60 s per key, key =
  `CF-Connecting-IP`. Per-location semantics accepted (abuse mitigation, not
  accounting).
- **CORS**: `Access-Control-Allow-Origin: *`; methods `GET, POST, OPTIONS`;
  headers `content-type`. Handled via Hono `cors` middleware.
- **Logging**: route + status only. SDP bodies MUST NOT be logged.
- **Config**: vars `SESSION_TTL_SECONDS=90`, `TURN_KEY_ID`; secret `TURN_API_TOKEN`.

# QP/1 — QR / Offline Signaling Protocol

Version: QP/1 · Status: normative for M4 · Governing decisions: D2, D12, D15

Same handshake as SP/1 (one offer SDP, one answer SDP, non-trickle), transported
over animated QR frames or a copy-paste blob instead of HTTP. Both sides need a
display and a way to read the peer's payload (camera **or** paste). ICE servers
follow policy D15: preset `none` (default) = host + STUN only, **zero CF contact**
(fully-offline contexts degrade to host candidates automatically); preset
`fallback` adds TURN from an anonymous `GET /v1/ice` — no session is created.

## Payload

1. JSEP JSON `{"type":"offer"|"answer","sdp":"…"}` (no munging in v1).
2. Compress with zlib (deflate). → `payload` bytes.
3. `crc32 = CRC-32/IEEE of payload` (uint32).

## QR frames

Binary frame, QR byte mode, EC level M:

```
offset  field
0       "JSI1"            4 B  magic
4       seq               2 B  uint16 BE, 1-based
6       total             2 B  uint16 BE
8       crc32             4 B  uint32 BE, of full payload
12      chunk             N B  payload[(seq-1)*chunkSize : seq*chunkSize]
```

- Default `chunkSize` = **400 B** (final value set by spike M4.1 measurement).
- Frames render as a looping animation at ~2 fps (adjustable), quiet zone ≥ 2
  modules, terminal half-block rendering (`mdp/qrterminal/v3`).
- Decoder: collect frames until all `total` seen (any loop pass), order by `seq`,
  concatenate, verify `crc32`, inflate. Frames with wrong magic/length are skipped.

## Paste format (fallback channel)

Single line, for terminals without cameras:
`jsi1:` + base64url(no padding) of the **same** `payload` (unframed).
Decoder path: strip prefix → base64url-decode → verify crc32? — the crc is not
embedded in the paste format; integrity comes from zlib's own checksum + the
subsequent DTLS handshake. (Rationale: paste is human-mediated, frame loss is N/A.)

## Sequence

```
Sender                              Receiver
  │  display offer frames (loop)      │
  │ ────────── scan ─────────────────▶│
  │                                   │  display answer frames (loop)
  │◀───────────────── scan ───────────│
  │  WebRTC connect (host candidates) │
```

Scan timeout: 120 s per direction. Preset `none`: fail with instructions.
Preset `fallback`: announce the escalation to the user, then continue via SP/1
worker signaling (proposal M4: "falling back to CF only when needed").
